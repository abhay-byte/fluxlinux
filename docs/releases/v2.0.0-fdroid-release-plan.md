# FluxLinux 2.0.0 — GitHub release + F-Droid update plan

**Status:** do **not** tag or push until the blockers in §3 are closed.  
**Target:** `versionName 2.0.0` / `versionCode 12` → F-Droid package `com.ivarna.fluxlinux`.  
**Live F-Droid:** 1.8.0 (`versionCode` 10). Auto-update is on (`AutoUpdateMode: Version`, `UpdateCheckMode: Tags`) but the **existing recipe cannot build 2.0.0**.

This is an **update MR**, not a new-app MR. Do not reuse `~"New App"` from `docs/releases/fdroid_mr_description.md`.

---

## 1. Verdict (policy + build)

| Area | Verdict |
|------|---------|
| Inclusion (FLOSS app, no Play Services / Firebase / Crashlytics) | **Pass** — Kotlin/Compose + Termux/X11, GPLv3, no proprietary SDKs |
| Trusted Maven deps (AndroidX, OkHttp, Haze, JitPack `termux-app` v0.118.0) | **Pass** — JitPack is an allowed source **if** the AAR is FLOSS (termux-app is GPLv3) |
| Product flavors | **Will break auto-update** — F-Droid must run `assembleIvarnaRelease`, not `gradle: yes` |
| Host bootstrap (`bootstrap.tar` gitignored; 196 `.deb`s tracked) | **Build blocker** unless the fdroiddata recipe runs `assemble_bootstrap.py` |
| Prebuilt `.so` / `.deb` / `loader.apk` / `libXlorie.so` | **Scanner blocker** without an updated `scanignore` + source pointers |
| Reproducible / `AllowedAPKSigningKeys` | **At risk** — `tar -cf` in `assemble_bootstrap.py` is not timestamp-stable |
| Runtime downloads (rootfs, Mesa/Turnip, optional SDK/NDK) | **Already `TetheredNet`** — expand the text; add opt-in consent copy |
| Fastlane / privacy copy | **Stale** — still claims Termux + AccessibilityService (removed from the manifest) |

Nothing in 2.0.0 looks like a **hard inclusion reject** (no tracking SDK, no Play Services). The release will **fail F-Droid CI / reproducible publish** if you only tag and wait for the bot.

## 2. What changed since the last F-Droid build (1.8.0)

The last published recipe (`gitlab.com/fdroid/fdroiddata` `metadata/com.ivarna.fluxlinux.yml`) is:

```yaml
gradle: [yes]
scanignore: [assets/xfce4/icons/..., theme.zip, cursor.zip, wallpaper.zip]
Binaries: https://github.com/abhay-byte/fluxlinux/releases/download/v%v/app-release.apk
CurrentVersion: 1.8.0
CurrentVersionCode: 10
AntiFeatures:
  TetheredNet: Depends on Github, Gitlab, kcubeterm.com, easycli.sh and more ...
```

2.0.0 in this tree is a different app:

- Dual flavors: `ivarna` (`com.ivarna.fluxlinux`) and `zenithblue` (`com.zenithblue.fluxlinux`).
- Gradle fail-closed on `native/bootstrap/<id>/bootstrap.tar` + four `jniLibs` (see `app/build.gradle.kts` `packageHostAssets*`).
- `bootstrap.tar` (~124 MiB) is **gitignored**. Tracked inputs are `native/output/com.ivarna.fluxlinux/*.deb` (196 files) + `native/bootstrap/.../jniLibs/*.so`.
- Embedded terminal + vendored `termux-x11` (prebuilt `libXlorie.so` for 4 ABIs).
- Rootfs **not** in the APK; downloaded from `https://github.com/abhay-byte/fluxlinux/releases/download/rootfs/...`.
- `ApkDownloader.kt` deleted — no more sideloaded Termux APKs (good).
- AccessibilityService is **gone** from `AndroidManifest.xml` (no `BIND_ACCESSIBILITY` anywhere).
- `kcubeterm` / `easycli` **do not appear** in the current tree — the live TetheredNet blurb is stale.
- Local `com.ivarna.fluxlinux.yml` is **behind** fdroiddata (missing 1.7 / 1.8.0, wrong license string, no AntiFeatures).

GitHub v1.8.0 published **`app-release.apk`**. Flavor builds now emit **`app-ivarna-release.apk`**. The `Binaries:` template still expects `app-release.apk`.

## 3. Blockers to close before tagging

Do these on `main` (or a release branch that you tag). Do not tag `v2.0.0` while the working tree is dirty.

### 3.1 Finish or park the uncommitted 2.0.0 work

Working tree currently has ~72 dirty/untracked paths, including PulseAudio host/guest (`PulseHost.kt`, `AudioSettingsScreen.kt`, family setup scripts, `bootstrap-host.txt` / `termux-lib-ssot.txt`). `versionName` is already `2.0.0` on `origin/main`.

- If PulseAudio is in 2.0.0: commit, restage `native/bootstrap/com.ivarna.fluxlinux` via `assemble_bootstrap.py` + `package_host_assets.sh`, rebuild the ivarna release APK.
- If it is not: revert those files before the tag so F-Droid builds the same tree you ship.

### 3.2 Make `bootstrap.tar` reproducible

`scripts/assemble_bootstrap.py` `create_tarball()` uses plain `tar -cf`. Different `mtime` / uid on the F-Droid builder vs your machine → different `assets/bootstrap.tar` → DEX/resources match but APK hash fails → **reproducible publish is skipped**.

Change the pack step to something equivalent to:

```bash
tar --sort=name --mtime=@0 --owner=0 --group=0 --numeric-owner -cf bootstrap.tar usr
```

(or honor `SOURCE_DATE_EPOCH`). Re-run `assemble_bootstrap.py` twice and confirm identical SHA256.

Point `--loader-apk` at the **tracked** file `app/src/main/assets/loader.apk`. The script default `native/loader/shell-loader.apk` is gitignored and will be missing on F-Droid.

### 3.3 F-Droid recipe will not infer itself

`assembleRelease` now builds **both** flavors. F-Droid `gradle: yes` is wrong: it would try `zenithblue` (Play id) and still fail because `bootstrap.tar` is absent.

You **must** open an fdroiddata MR with an explicit 2.0.0 `Builds:` entry (`gradle: [ivarna]` + `sudo` assemble). Do not rely on the checkupdates bot copying the 1.8.0 recipe.

### 3.4 Scanignore + source notes (Inclusion Policy)

Policy: prebuilts only from Debian main, trusted Maven, or documented FLOSS with `scanignore` + reason.

Tracked blobs the scanner will flag:

| Path | What | Source to cite |
|------|------|----------------|
| `native/output/com.ivarna.fluxlinux/*.deb` (and zenithblue twin) | Termux-prefix packages | Built from [termux-packages](https://github.com/termux/termux-packages) via `scripts/build_packages_for_appid.sh` |
| `native/bootstrap/*/jniLibs/arm64-v8a/lib{bash,proot,loader,loader32}.so` | Copied from those debs | Same; regenerated by `assemble_bootstrap.py` |
| `termux-x11/src/main/jniLibs/*/libXlorie.so` | X11 renderer | [termux/termux-x11](https://github.com/termux/termux-x11) (Java is in-tree; `.so` is prebuilt) |
| `app/src/main/assets/loader.apk` | 2.3 KiB X11 loader | termux-x11 `shell-loader` |
| `app/src/main/assets/scripts/opensuse/common/libevp_md2.so` | Guest helper | Must have a license/source comment in the MR |
| `app/src/main/assets/xfce4/**/*.tar.xz` + repo `assets/xfce4/**` | Themes/icons/cursors | Papirus GPLv3, Vimix GPLv3, Space theme |

Old scanignore paths (`papirus-icon-theme-20250501.tar.gz`, `theme.zip`, `cursor.zip`) are **not** what the app module ships now.

### 3.5 Runtime binary downloads (Inclusion § Security)

Policy: do not download extra **executables** without **opt-in** consent that the user is bypassing F-Droid’s checks.

User-initiated, but **missing** that sentence today:

- Onboarding / distro install → `RootfsDownloader` (full Linux rootfs from GitHub `rootfs` tag).
- Guest HW accel → Mesa/Turnip tarballs (`setup_hw_accel_guest.sh`).
- Optional stacks → Android SDK/NDK zips, Godot, Heroic, etc.

Add a short disclosure on the first install confirm (and keep TetheredNet). Optional stacks that enable Debian/Kali `non-free` may get **`NonFreeAdd`** — disclose in the MR; do not hide it.

Update the live TetheredNet string (drop kcubeterm/easycli; name GitHub `rootfs` + `debian-v1` assets).

### 3.6 Fastlane / listing must match the app

Quality rule: the app must implement what the description says.

`fastlane/metadata/android/en-US/full_description.txt` still says **Requirements: Termux, Termux:X11** and **AccessibilityService**. Both are false for 2.0.0 (embedded host + X11; accessibility removed).

Also refresh:

- `fastlane/README.md` (still 1.8.0 / versionCode 10).
- `docs/privacy_policy.md` (still overlay / RUN_COMMAND as core; last updated Jan 5, 2026).
- `CHANGELOG.md` Unreleased section (does not mention embedded host, multi-distro catalog, on-demand rootfs, PulseAudio).
- `fastlane/.../changelogs/12.txt` exists (good). There is **no** `11.txt` — versionCode 11 was skipped; that is fine.

### 3.7 License string

- Repo `LICENSE` = GPL-3 text (no “or later” in a header).
- fdroiddata = `GPL-3.0-only`.
- Local `com.ivarna.fluxlinux.yml` = `GPL-3.0-or-later`.

Keep **`GPL-3.0-only`** in fdroiddata unless you add an explicit “or later” notice in the repo.

## 5. Release sequence (do in this order)

### Phase A — Freeze the tree

1. Land or revert PulseAudio / dirty files.
2. Land §3.2 (reproducible tar + loader path), §3.6 Fastlane/privacy, §3.5 consent line.
3. Sync `com.ivarna.fluxlinux.yml` to fdroiddata + the new Builds stub (commit SHA filled after tag).
4. `CHANGELOG.md`: retitle Unreleased → `## v2.0.0` and list the real 2.0.0 features (embedded host, 12 distros, on-demand rootfs, PulseAudio if shipped).
5. Write `docs/releases/v2.0.md` from that changelog (same pattern as `v1.8.md`).
6. `git status` clean.

### Phase B — Verify the **ivarna** APK locally

```bash
python3 scripts/assemble_bootstrap.py \
  --package-name com.ivarna.fluxlinux \
  --list native/package-lists/termux-lib-ssot.txt \
  --mode full \
  --loader-apk app/src/main/assets/loader.apk

./scripts/verify_bootstrap.sh com.ivarna.fluxlinux
./scripts/package_host_assets.sh com.ivarna.fluxlinux   # also run by Gradle

./gradlew :app:testIvarnaReleaseUnitTest
./gradlew :app:assembleIvarnaRelease

./scripts/verify_apk_host_assets.sh \
  app/build/outputs/apk/ivarna/release/app-ivarna-release.apk
```

Checks:

- `aapt dump badging` → `package: name='com.ivarna.fluxlinux'` `versionCode='12'` `versionName='2.0.0'`.
- APK contains `assets/bootstrap.tar` and `lib/arm64-v8a/lib{bash,proot,loader,loader32}.so`.
- APK contains **zero** `assets/rootfs/*`.
- Signing cert SHA-256 is still `34f011660e5bb7140de5452e169e1399fd0e6586746daa5431d29d637f6d1a3c` (same `fluxlinux.jks` / `AllowedAPKSigningKeys`).
- Size ~150 MiB (current local ivarna release is 150M).

Rename for the F-Droid `Binaries:` URL (do not change the signed bytes):

```bash
cp app/build/outputs/apk/ivarna/release/app-ivarna-release.apk /tmp/app-release.apk
```

Optional but recommended: run `fdroid build -v -l com.ivarna.fluxlinux` against a local fdroiddata checkout with the new recipe.

### Phase C — GitHub tag + release

Tag format must stay `v2.0.0` (`UpdateCheckMode: Tags` already consumed `v1.8.0`).

```bash
git checkout main
git pull --ff-only
git tag -a v2.0.0 -m "Release v2.0.0"
git push origin main
git push origin v2.0.0

gh release create v2.0.0 \
  /tmp/app-release.apk \
  --title "v2.0.0" \
  --notes-file docs/releases/v2.0.md
```

Asset **must** be named `app-release.apk` at:

`https://github.com/abhay-byte/fluxlinux/releases/download/v2.0.0/app-release.apk`

Confirm with `curl -sI` → HTTP 200 (after redirects). If you only upload `app-ivarna-release.apk`, reproducible matching against `Binaries:` fails.

Also confirm the **`rootfs`** release still has all 12 archives + matching SHAs (`scripts/verify_rootfs_shas.sh` / `upload_rootfs_release.sh --check`). The APK does not contain them.

### Phase D — fdroiddata MR (required; do not wait for the bot)

Per [CONTRIBUTING.md](https://gitlab.com/fdroid/fdroiddata/-/blob/master/CONTRIBUTING.md):

1. Fork `https://gitlab.com/fdroid/fdroiddata` (or update your existing fork).
2. Keep `master` clean; branch `com.ivarna.fluxlinux` (one app per branch).
3. Edit **only** `metadata/com.ivarna.fluxlinux.yml`:
   - Append the §4 Builds entry with the real tag SHA.
   - Set `CurrentVersion` / `CurrentVersionCode`.
   - Refresh `TetheredNet` text.
   - Optionally add `NonFreeAdd` if reviewers want Kali/Parrot `non-free` + SDK stacks declared.
4. Commit, push, wait for **your fork’s CI** (`fdroid lint` / `readmeta`). Fix YAML before opening the MR.
5. Open the MR against `fdroid/fdroiddata` `master`. Squash is on by default.

This is **not** a new-app submission. Use the update checklist in §6.

If the checkupdates bot opens a competing MR that copies `gradle: yes`, comment with a link to yours and close the bot MR.

### Phase E — After merge (you wait)

F-Droid build cycle is typically several days ([wiki FAQ](https://gitlab.com/fdroid/wiki/-/wikis/FAQ#how-long-does-it-take-for-my-app-to-show-up-on-website-and-client)). Watch:

- fdroiddata pipeline on the merged commit.
- [F-Droid monitor](https://monitor.f-droid.org/) / build log for `com.ivarna.fluxlinux:12`.
- Reproducible match: if it fails, the unsigned F-Droid APK is **not** published under your key; fix tar reproducibility and ship 2.0.1.

Do **not** bump version again until 12 is green or you know you need a fixup tag.

```markdown
## Required

* [x] The app complies with the Inclusion Policy
* [x] I am the upstream author
* [x] Related issues referenced (none open for this update)
* [ ] Builds with `fdroid build` / fork CI green

## Update

Bump **FluxLinux** `com.ivarna.fluxlinux` **1.8.0 (10) → 2.0.0 (12)**.

2.0.0 embeds the Termux-prefix host (bootstrap + proot) and Termux:X11. External Termux is no longer required. Distro rootfs archives are downloaded on demand from the GitHub `rootfs` tag (SHA256-pinned). Product flavor `ivarna` is the F-Droid/GitHub id; `zenithblue` is Play-only and must not be built.

### Build recipe changes

* `gradle: [ivarna]` — `gradle: yes` / `assembleRelease` would also configure the Play flavor.
* `sudo`: assemble `bootstrap.tar` from tracked `.deb`s (`scripts/assemble_bootstrap.py`). The tarball is gitignored (~124 MiB).
* `scanignore`: Termux `.deb`s / host `.so`s, `libXlorie.so`, `loader.apk`, XFCE theme archives. All FLOSS; sources cited below. Not used as F-Droid compile inputs except via the assemble script.
* `Binaries:` still `.../v%v/app-release.apk` (ivarna APK uploaded under that name).
* `AllowedAPKSigningKeys` unchanged.
* `TetheredNet` text updated (GitHub `rootfs` / `debian-v1`; kcubeterm/easycli removed).

### Sources for prebuilts

* Host packages: termux-packages, rebuilt with applicationId `com.ivarna.fluxlinux` (`native/README.md`).
* `libXlorie.so` / `loader.apk`: termux/termux-x11 (Java vendored under `termux-x11/`).
* Papirus / Vimix / Space theme archives: GPLv3 / project assets, extracted at runtime.

### Consent

Install is user-initiated. Rootfs / GPU driver / optional SDK downloads are not silent auto-updates. Listing already has TetheredNet.
```

## 7. What not to do

- Do not upload `app-ivarna-release.apk` as the only asset.
- Do not tag from a dirty tree or from a commit that cannot assemble without local `app/src/ivarna/assets/bootstrap.tar` already present (F-Droid will not have it until `sudo` assemble).
- Do not point F-Droid at `zenithblue` (different applicationId; Play signing).
- Do not add Google Maven-only proprietary libs in a last-minute 2.0.0 commit.
- Do not use the old “New App” MR template or claim AccessibilityService / bundled BusyBox NDK zip (those are gone).
- Do not change `AllowedAPKSigningKeys` unless you rotated the keystore (you have not).
